## 启动器的方案演变

Codex 的启动排障记录包含三段工作。

1. 旧服务信息的项目目录不匹配，触发 `record-project-root-mismatch`。
2. 曾手动备份运行状态，并用备份构造隔离测试。记录显示安装包 0.6.23 启动后仍会回写不一致的项目目录。
3. 实施总结称脚本复用了运行中的服务，在服务退出时备份并重启，返回 HTTP 200。检查 `.stale-*` 备份的历史测试退出码为 1，自动备份分支的验收证据仍不足。

2026-11-13，Antigravity 排查了重跑后仍加载旧界面的问题。用户要求启动时自动检测并构建，随后更新了启动器。现行脚本按时间戳重建、同步产物、指定 `--admin-root` 并按需重启。

旧版脚本曾用 `Move-Item` 将过期记录改名为 `.stale-<GUID>` 后重试。现行实现改用健康检查、按需停止旧进程并删除过期记录后重试。旧版自动备份分支缺少成功验收记录。脚本位置和版本组合见 [CUST-004](changes/CUST-004.md)。

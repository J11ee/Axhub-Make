## 日常开发流程

1. 查看相关档案和上游基线。用 `git show <上游基线>:<路径>` 阅读原实现，核对本地差异、调用方和兼容数据。优先沿用既有实现。
2. 同一功能更新原档。独立事项使用下一个未用编号，从 [模板](TEMPLATE.md) 建档并补索引。状态或摘要变化时同步索引。代码位置使用仓库相对路径，并补充能说明实际修改的符号、提交或验证。
3. 交付前检查实际差异及相关测试，再运行下面的登记检查。逐项核实同一文件涉及的全部改造，尤其是共用侧栏文件、协议和持久化路径。

纯行尾、排版和无语义机械改动可豁免，交付时说明依据。原样上游同步在升级记录登记版本和验证。同步中发生的本地行为变化仍需更新对应档案。工作区外的部署脚本由人工核对。测试变更与所验证的行为关联，单独补充测试可说明其维护性质。

## 登记检查

在源码仓库执行 `node scripts/check-customizations.mjs [比较基线]`。默认与 `HEAD` 比较，检查暂存和工作区差异及未跟踪文件，按仓库相对路径匹配本次新增或更新的档案。已提交变更需传入任务开始前的提交。首次接手已有未提交改动时，先记录任务开始前的差异，再人工确认哪些路径属于本次任务。

检查提示可能缺档或路径不匹配。共享文件命中一条记录无法证明所有行为均已登记。批量上游同步和机械维护按上面的豁免边界复核。命令为手动运行的本地检查，无 Git Hook 或外部依赖。

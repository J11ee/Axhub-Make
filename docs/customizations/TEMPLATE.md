# CUST-xxx 改造名称

- 模块
- 类型（新增、修改、替换、移除、缺陷修复）
- 状态（规划中、已实现、部分实现、已讨论未实施、已实施但已移除、已被替代、待核实）
- 首次提出日期（无证据时写待核实）
- 首次实施日期（未实施或待核实据实标注）
- 最近更新日期

## 原始需求和原生行为

记录触发问题、使用场景、上游基线及对应实现、采用的 P0～P5 方案和选择理由。涉及审批时记录用户确认的范围与决定来源。

## 实际实现

说明实际行为和与上游的差异，注明重要入口、组件或函数。写明是否改变核心源码、公共接口、数据结构或 AI 工作流，以及兼容影响。仍在讨论的方案标注其计划状态。

## 关联路径

- `src/实际文件.ts`

这里使用单独的反引号列表记录精确仓库相对路径。确需覆盖整个目录时以 `/` 结尾。仓库外路径放在「实际实现」中说明，以便人工核对。

## 实施与变更记录

按日期追加每次实质性变更，记录本次改了什么、原因和对应的文件或代码入口。能核实的日期用 `YYYY-MM-DD`，未知时标注待核实。

## 历史证据

分别记录需求与决定来源、代码证据和验证证据。注明会话 ID 或材料位置。已有 Git 提交时记录可确认的提交号，未提交时标注未提交。已有方案被替代时注明时间、原因和可能的恢复来源。

## 上游升级影响

记录原生文件、依赖的公共契约、升级必查项以及回归上游的条件。

## 启停与回退

记录适用的开关、默认值和关闭后的行为。说明可执行的回退步骤，包括需恢复的配置、提交或构建产物，以及旧数据的兼容、备份或恢复条件。存在无法完整恢复的部分时写明限制。

## 验证与遗留

记录日期、运行入口及实际加载的版本或产物、验证命令或场景及结果。分别标注已通过、失败、未验证和待用户验收的事项，并说明已知风险。涉及 AI 工作流时附原有路径和新增路径的验证结果。

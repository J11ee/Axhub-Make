## 升级评估

1. 确认现基线、目标上游标签及解析后的完整提交号。用 `git ls-remote` 核对公开引用。浅克隆缺对象时，先用 GitHub 提交或 Compare 页面，也可在独立目录准备可比较的上游源码。
2. 查看 `git log --oneline <旧基线>..<目标>`、`git diff --find-renames --name-status <旧基线> <目标>` 和相关补丁。对照发布说明、测试和实现，识别功能、架构、接口、数据结构、缺陷修复及文件移动。
3. 对照索引、当前已提交和未提交差异及外围启动器。查本地与上游共同修改的文件，也沿调用关系查消息、公共接口、配置、数据兼容和 UI 行为。文件分开仍可能有行为冲突。
4. 每项受影响改造记录本地和上游做法、文本冲突、行为差异、回归验证和处理建议（保留、调整、替换或回归上游）。上游已有等价能力时核实旧数据和关键工作流，再评估采用条件。
5. 获得授权后按确认方案实施。验证实际运行和历史使用场景，更新本文件、[升级记录](UPGRADE_LOG.md)、对应档案和 [索引](README.md)。同步前后均核对暂存区、工作区和外围启动依赖。
